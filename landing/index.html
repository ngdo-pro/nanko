POURQUOI NANKO

Un diagramme qu'on n'a pas peur de rouvrir six mois plus tard.

01

La base de données fait autorité

La base de données est la source de vérité du contenu et des Version d'un Document. Le fichier .nanko n'existe qu'aux points d'export et d'import, jamais en synchronisation continue.

02

Le rendu est déterministe

Le Layout vit dans le même fichier .nanko que le contenu, versionné avec lui. Généré une seule fois à l'import, il est ensuite piloté à la main : jamais régénéré, jamais mélangé au contenu.

03

Les versions racontent la migration

Une cible, des jalons intermédiaires, une Current version choisie à la main. Chaque jalon livré peut la devenir ; la précédente rejoint l'historique du Layer sans disparaître.

LE VOCABULAIRE

Six mots-clés couvrent le cœur du modèle.

Le modèle reste volontairement petit : un Document versionné, un Draft éditable, une Current version choisie à la main. Le contenu ne porte jamais de position, Nanko s'occupe du placement dans le Layout.

document Un schéma versionné, identifié par un @id stable, positionné sur un Layer.
layer L'attribut de profondeur d'un Document dans un Project, pas une entité séparée.
version Un instantané figé et immuable d'un Document, identifié par @version (layer:semver).
draft L'état de travail courant d'un Document, modifiable librement, distinct de ses Version figées.
current version La Version désignée à la main comme faisant autorité pour la navigation inter-Layer.
satisfies La déclaration de compatibilité @satisfies layer:range : avertit, sans jamais choisir automatiquement.
MIGRATIONS

De l'architecture actuelle à la cible, par jalons.

Posez la cible, découpez le chemin en jalons datés. Quand un jalon est livré, promouvez-le en Current version : la précédente rejoint l'historique du Layer sans disparaître.

SOUS LE CAPOT

Des choix volontairement simples, pas encore sur-conçus.

Nanko n'ajoute une brique que quand un besoin réel la justifie. Le format d'échange, la recherche, les droits et le canvas suivent la même logique.

EXPORT / IMPORT

Le fichier ne vit qu'aux deux bouts

.nanko n'est jamais stocké par Nanko : la base de données est la source de vérité, le fichier n'existe qu'à l'export et à l'import.

RECHERCHE

Le plein texte remplace le rangement

Pas de dossiers ni de hiérarchie dans un Project : une recherche plein texte intégrée retrouve vos Document, sans moteur ni cache dédiés.

DROITS

Une Capability par Project, jamais implicite

Être membre d'une Org ne donne accès à aucun Project par défaut. Une Org peut définir une Capability par défaut pour couvrir le cas d'une petite équipe.

CANVAS

2D d'abord, l'isométrique en support

L'édition reste un canvas 2D top-down en v1. Un helper de navigation en pile de layers, isométrique et statique, aide à s'y repérer sans passer par la 3D.
