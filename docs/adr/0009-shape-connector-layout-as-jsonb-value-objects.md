# Shape, Connector et Layout sont des value objects sérialisés en JSONB, pas des tables normalisées

Le contenu (`Shape`/`Connector`) et le `Layout` d'un Document sont stockés comme des value objects PHP sérialisés dans des colonnes `content`/`layout` en JSON, sur `Draft` et `Version`, plutôt que dans des tables normalisées avec une ligne par forme/connector. Aucun besoin v1 de requêter ou joindre à l'intérieur du contenu d'un document (la seule recherche prévue est au niveau document, via un futur `tsvector`, ADR-0007) ; normaliser forcerait un fan-out de N inserts par publication de Version et compliquerait la reconstruction de l'ordre d'origine, nécessaire pour le futur sérialiseur `.nanko`. L'unicité des ID de Shape et la validité des références des Connector sont vérifiées côté application (`DocumentContentValidator`), pas par des contraintes ou triggers Postgres, dans le même esprit que l'ADR-0007.
