Rendu de la flèche : pas de nouveau type d'edge — un edge React Flow générique (`type: "straight"`, `strokeDasharray`, `markerEnd: ArrowClosed`, couleur `--note-border`) construit à la volée pour chaque note liée, `selectable: false` et exclu de l'état `edges` (jamais persisté comme une vraie relation, jamais sélectionnable dans `RelationPanel`). Lien uniquement vers un **élément** dans cette passe — lier à une **relation** (un edge) n'a pas d'équivalent "glisser sur un edge" nativement supporté par React Flow ; la colonne `relation_id` reste en base et acceptée par l'API pour plus tard, juste sans UI de création.
  - **Composer — afficher/retirer le lien, pas le créer** — `AnnotationComposer` gagne une ligne "Linked to X" + bouton Unlink quand un lien existe (nom de l'élément résolu depuis les noeuds déjà chargés, pas un fetch séparé) ; la popover ne sait pas *poser* de lien, volontairement — poser un lien reste un geste sur le canvas, cohérent avec le fait que retirer ("Unlink") est la seule action symétrique qui a du sens dans une popover de texte.
  - **Édition inline — même popover pour créer et éditer, mais un deuxième chemin plus court** — double-clic sur un post-it bascule son texte en `<textarea>` directement dans le noeud (classes `nodrag nopan` pour ne pas déclencher un drag React Flow au clic), plutôt que d'ouvrir le composer complet. Simple clic garde l'ancien comportement (popover complet, pour toucher l'auteur ou le lien) — les deux coexistent, l'un ne remplace pas l'autre. Perte de focus (`blur`) commit, `Escape` annule sans sauvegarder. Un clic puis un double-clic (comportement natif du navigateur : les deux événements se déclenchent en séquence) ouvre puis referme immédiatement le composer — accepté comme compromis mineur, même famille de compromis déjà acceptée pour le double-clic de drill-down sur les éléments.
  - Les callbacks d'édition (`onCommitEdit`/`onCancelEdit`/`isEditing`) ne sont **pas** stockés dans l'état persistant `annotationNodes` (qui reste un miroir pur de la forme API, relu/réécrit tel quel par `onNodesChange` après un drag) — injectés séparément dans un tableau dérivé au moment du rendu, pour ne pas polluer l'état source de vérité avec des fonctions.
  - 6 nouveaux tests frontend (`AnnotationNode.test.tsx` : mode édition, commit au blur, annulation à Escape ; `AnnotationComposer.test.tsx`, nouveau fichier : lien affiché/absent, Unlink, trim auteur/corps).
  - Vérifié en navigateur réel sur "Canvas Demo" : post-it créé, flèche tirée jusqu'à "Booking" par glisser-déposé (rendu en tireté immédiatement, confirmé en base via `curl` — `element_id` renseigné), Unlink confirmé (flèche disparaît, `element_id` revient à `null`), double-clic → édition inline → texte modifié persisté au blur (`GET /annotations` confirme le nouveau corps).
